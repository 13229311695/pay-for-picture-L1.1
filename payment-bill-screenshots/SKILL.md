# 支付账单截图批量复刻

## 输入 / 产出

- 输入：一份 Excel（`.xlsx`/`.xls`，首个子表），表头含上述列（允许「交易对方/对方账号/订单标题」这类 `/` 复合表头）。
- 产出：每行一张 PNG，文件名为 `MM-DD <项目名>[-2][-3].png`；全部放在一个文件夹内，再打包为 `*.zip`。
- 只处理 `支付来源 = 微信支付 / 支付宝 / 美团` 三种；其他来源（银行卡、云闪付、现金等）跳过并在回执里列出。

## 执行流程

以下命令都在本 Skill 目录下执行（`scripts/…`、`assets/…` 均为相对本目录的路径）；输出目录用用户项目目录。

1. **确认输入**：拿到表格路径。表头缺列时脚本会回显 `missing_columns`，据此向用户确认，不要凭猜测补列。
2. **映射生成清单**（逐行判定，不改原表）：

   ```bash
   python3 scripts/prep.py --xlsx "<表格路径>" --workdir <工作目录>
   ```

   回执含 `total`、`by_source`、`skipped`、`missing_columns`，以及 `workdir/manifest.json`。
   `skipped` 非空时要向用户说明跳过了哪些行。
3. **逐条渲染**（脚本内部串行：一条渲染完成再下一条，对应「一个项目的执行后再执行下一个」）：

   ```bash
   python3 scripts/render.py --workdir <工作目录> \
     --templates assets/templates --out <图片目录> --zip <输出zip路径> [--folder 支付截图]
   ```

   尺寸固定：微信 955×2048@2x、支付宝 958×2048@2x、美团 1284×2778@1x。
4. **抽检 3 张**（每组各一张，优先挑商品/商户名最长的记录），确认无截断、无压盖、金额符号正确，再把 zip 交出去。
5. **交付**：zip 通过产物交付工具（`present_files`）交给用户；回复给出张数、各来源数量、跳过项、文件名去重说明。

| --- | --- | --- |

| 微信 | 商品 | 商品/商品说明/交易内容 |
| 微信 | 商户全称、商户名称 | 交易对方/对方账号/订单标题 |
| 微信 | 收单机构 | 固定「微信支付」 |
| 微信 | 支付方式 | 支付方式/交易方式 |
| 微信 | 交易单号 | 交易单号/交易订单号/订单号 |
| 微信 | 商户单号 | 商户单号/商家订单号/商家单号 |
| 微信 | 商家小程序 | 固定「在线点单」 |
| 微信 | 金额 | 负数、两位小数（`-32.46`） |
| 支付宝 | 支付时间 / 商品说明 / 商户名称 / 付款方式 | 支付时间 / 商品 / 交易对方 / 支付方式 |
| 支付宝 | 账单分类 | 固定「其他」 |
| 支付宝 | 标签 | 固定「请选择」 |

## 微信 Logo 选择（01–04）

- `01` 美团-大众点评：交易对方或商品含「美团」「大众点评」
- `02` 店铺-超市-餐饮：默认（绝大多数餐饮/超市/便利店）
- `03` 个人转账-群收款：商品/交易内容含「收款方备注:二维码收款」「转账」「群收款」
- `04` 其他支付：含缴费/话费/充值/停车/水电/燃气/物业/快递/打车/加油/保险等

这套规则是默认口径，不是唯一正确答案。交付时说明本次各 logo 命中的条数；用户若给出更细口径（例如某几笔按转账算），只调整 `prep.py` 的 `pick_logo` 后重跑，不要改模板。

## 文件名

- `MM-DD <项目名>.png`，不含年份；项目名原样，`/` 换成「、」，其余非法字符换全角。
- 同日同项目重复时，第 2 条起追加 `-2`、`-3`，保证唯一且不覆盖。
- 不分平台建子文件夹，全部平铺在一个文件夹里打包。

## 环境依赖

`python3` + `openpyxl` + `playwright`，以及一个可用 Chromium。`render.py` 的 `find_chrome()` 会自动在 `/opt/vm/preinstall/ms-playwright/chromium-*/chrome-linux/chrome`、`/usr/local/bin/chromium`、`/usr/bin/chromium`、`google-chrome` 之间择一；都没有才回落到 playwright 自带浏览器（需先 `playwright install chromium`）。

模板在 `assets/templates/`：`wechat01.html`、`alipay02.html`、`meituan03.html`。它们是可编辑的界面复刻稿，自带编辑器面板，渲染时只截手机根元素，不截整页。

## 三个模板的注入方式差异（改脚本前必读）

- `wechat01.html`：`state` 是顶层 `const`，直接 `Object.assign(state, payload); render();`。截 `#screen` 前要先把 `#screenShell` 固定为 955×2048 并把 `#screen` 的 `scale()` 置 `none`，否则会被缩放或裁切。
- `alipay02.html`：`state` 封在 IIFE 内，外部改不到。做法是把 payload 写进 `<script id="saved-state" type="application/json">null</script>` 后另存临时文件重新加载（用完删除临时目录）。
- `meituan03.html`：`state` 是顶层 `let`，可 `Object.assign`。SVG 受 `.frame svg{width:100%}` 约束，必须把 `.frame` 与 `#bill` 都压到 1284×2778 才能按原尺寸出图。

排错与已知坑见 [references/pitfalls.md](references/pitfalls.md)。
